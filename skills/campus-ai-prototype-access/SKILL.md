# 校园 AI 原型访问说明

这个 skill 用于编写或复核校园 AI 创作平台 MVP 原型的访问说明。目标是让不了解项目的人从公网进入页面，并完成学生端或管理员端的演示操作。

## 固定前提

- 原型后端运行在服务器上，`server.py` 只监听 `127.0.0.1:8080`。
- 公网入口由反向代理提供 HTTPS，再转发到 `127.0.0.1:8080`。
- 实际域名尚未确定。文档使用 `https://<待定域名>`，部署拍板后再替换。
- 学生端入口是 `https://<待定域名>/`，管理员端入口是 `https://<待定域名>/admin`。
- 所有账户、Token、密钥、实名名册和中转站数据都是演示数据。
- GitHub Pages 的静态页面不包含后端能力，不能替代运行 `server.py` 的服务器。

推荐用下面的转发关系说明代理，不要把后端改成监听公网地址：

```caddy
<待定域名> {
    reverse_proxy 127.0.0.1:8080
}
```

这段配置只表达代理到后端的关系。HTTPS、访问控制和其他安全参数按安全方案执行，不在本 skill 中新增设计。

## 学生端流程

1. 打开 `https://<待定域名>/`。
2. 选择“校园邮箱”或“学号”。
3. 输入身份和至少 8 位密码。
4. 首次使用点击“注册”，获得 100,000 Token 和一枚模拟中转站密钥。
5. 在页面首次显示时复制密钥明文。后续页面只显示密钥掩码。
6. 再次访问时使用相同身份和密码“登录”，查看余额、流水、模拟消耗或重新生成密钥。

说明访问流程时，明确告诉用户：原型使用账号密码模拟身份认证，不连接真实校园 SSO 或 CAS；密钥和 AI 调用也不连接真实中转站。

## 管理员端流程

1. 打开 `https://<待定域名>/admin`。
2. 输入部署时设置的 `ADMIN_PASSWORD`。
3. 按学号、邮箱或姓名搜索实名台账。
4. 查看学生编号、登录身份、姓名、密钥掩码和密钥状态。
5. 需要使当前密钥失效时，执行“吊销密钥”。

如果服务端没有设置 `ADMIN_PASSWORD`，管理员功能关闭。不要在回复、文档、提交或日志中写出实际管理员口令。

## 运行提示

需要说明启动方式时，保持后端本地监听：

```bash
HOST=127.0.0.1 PORT=8080 python3 server.py
```

不要建议把 `HOST` 改成 `0.0.0.0`，也不要把部署、开端口、改防火墙或安全加固步骤包装成这个 skill 已完成的工作。域名仍未确定时，保留 `<待定域名>`，不要猜测实际地址。
