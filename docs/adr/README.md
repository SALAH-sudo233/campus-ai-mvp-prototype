# 架构决策记录（ADR）

这里记录校园 AI 创作平台原型的架构与规范决策。每条决策写成一个独立文件，便于新共创者快速了解“为什么是现在这样”，也便于后续修改时追溯。

## 什么时候写 ADR

改动下面任何一类，都要先加或更新一条 ADR，再动代码：

- 整体架构、部署拓扑、对外边界。
- UI 规范：颜色、间距、字号、组件、交互。
- 开发规范：目录结构、依赖、命名、安全约定、数据库用法。
- 对外接口、数据模型、幂等与鉴权口径。

小的缺陷修复、文案调整、不改约定的实现，不用写 ADR。

## 怎么写

1. 复制最新编号加一，文件名用 `NNNN-短标题.md`。
2. 按模板写：背景、决策、后果。
3. 决策一旦被取代，不要删旧文件。把旧文件状态改成“已被取代”，注明日期和替代者，新决策另开一条。
4. 在下面的目录表里加一行。

状态取值：草案、已接受、已被取代、已废弃。
