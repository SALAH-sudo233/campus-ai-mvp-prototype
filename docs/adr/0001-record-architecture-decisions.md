# 0001 用 ADR 记录架构决策

状态：已接受
日期：2026-11-20

## 背景

原型从一个人起步，接下来会有其他共创者加入，还要继续改登录界面等模块。决策如果只留在聊天记录里，新人看不到，容易把定好的约定推翻重来。

## 决策

用架构决策记录（ADR，Architecture Decision Record）保存每一条架构与规范决策，放在 `docs/adr/`，一条决策一个文件。涉及架构、UI 规范、开发规范、对外接口的改动，先写或更新 ADR，再改代码。写法和状态规则见 `docs/adr/README.md`。

## 后果

- 新共创者读 `docs/adr/` 就能知道现在的约定和理由。
- 改约定要留痕：旧决策标“已被取代”，不删除，可以回溯。
- 多一步写文档的成本。只有改约定才需要，日常改 bug 不受影响。
