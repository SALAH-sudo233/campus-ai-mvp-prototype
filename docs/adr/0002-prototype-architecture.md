# 0002 原型整体架构与对外边界

状态：已接受
日期：2026-11-20

## 背景

原型要演示学生登录、领取 Token、从中转站拿密钥，让相关方能真实操作，同时不能影响同机的中转站 New-API。当前所有数据都是演示数据，正式版要换成学校认证和真实中转站。

## 决策

**范围**：只做学生登录和 Token、密钥发放。充值、支付、真实 AI 调用不在原型内。

**组成**：

| 模块 | 文件 | 职责 |
|---|---|---|
| 后端 | `server.py` | 注册、登录、会话、Token 账本、静态文件、管理员接口 |
| 模拟中转站 | `relay.py` | 发放和吊销密钥，维护实名台账 |
| 演示名册 | `roster.py` | 200 名模拟学生，同时是准入名单 |
| 学生端 | `index.html`、`app.js` | 登录、工作台、密钥、流水 |
| 管理端 | `admin.html`、`admin.js` | 实名台账、搜索、吊销密钥 |
| 部署 | `deploy/` | systemd、nginx 片段、部署脚本 |

**数据流**：

```text
学生浏览器 → nginx（HTTPS、限流）→ /app/ 去前缀 → 127.0.0.1:8080 server.py
                                                      ├─ demo-backend.sqlite（账户、流水、会话）
                                                      └─ relay.py → demo-relay.sqlite（密钥摘要、实名台账）
```

**边界约定**：

| 约定 | 说明 |
|---|---|
| 身份 | 原型用账号密码模拟。正式版接华中科技大学官方 SSO 或 CAS，平台不保存校园密码 |
| 准入 | 名册内的学号或邮箱才能注册和登录，名册外返回 403 或 401 |
| 学生编号 | `owner_ref` 是登录身份的 SHA-256 截断，只当台账和密钥的关联键，不是强匿名化 |
| 密钥 | 中转站只存 SHA-256 摘要。明文只在发放那一次返回，之后只给掩码 |
| 幂等 | 注册赠送、密钥发放、消耗都带请求编号，重复请求不重复发放或扣减 |
| 上游 | 中转站的上游通道是假数据，真实上游密钥不会返回给平台和学生 |
| 中转站隔离 | 原型以独立系统用户 `campus-proto` 运行，只占 nginx 的 `/app/` 路径，不改 New-API |
| 对外暴露 | 后端只监听 `127.0.0.1:8080`，对外只经 nginx。`/api/reset`、`server.py`、`relay.py` 在公网返回 404 |

## 后果

- 原型能整体搬走：账户和密钥逻辑集中在 `server.py` 和 `relay.py`，换成真实认证和中转站时，接口签名不变。
- `roster.py` 对外只暴露 `student_id_of`、`name_for`、`is_enrolled`，生产名册替换这个文件即可。
- 邮箱账号和学号账号在原型里是两个独立账户，不做归并。这是已知限制，由正式版统一认证解决。
- 用 SQLite 和标准库，部署简单，但不支持多实例并发写。原型规模够用，正式版需要换库。
