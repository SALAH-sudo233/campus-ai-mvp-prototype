# 0004 开发规范

状态：已接受（部分条款于 2026-11-24 被 0008、0009 取代）
日期：2026-11-20

> 部分取代：额度的唯一事实源改为 New-API（见 0008），平台数据库只作演示账面；鉴权从「只认服务端会话令牌」扩展为同时认 session 与 PAT（见 0009）。密码哈希、密钥摘要存储、参数化查询、同事务幂等等其余约定不变。

## 背景

接下来有多人一起改这个原型。把现有代码里已经在用的约定写下来，让新共创者照着做，保持风格一致，也守住安全底线。

## 决策

### 技术栈与依赖

- 后端只用 Python 3 标准库，不引第三方依赖。`python3 server.py` 直接能跑。
- 前端是原生 HTML、CSS、JavaScript，不引框架、不走构建。
- 数据库用 SQLite，开 WAL 模式。原型规模够用，不为它加 ORM。
- 新增依赖要先在 ADR 里说明理由，默认不加。

### 目录与文件

- 后端、前端、名册、部署文件都在仓库根目录，命名见 ADR 0002 的组成表。
- 部署相关文件放 `deploy/`。文档放 `docs/`，决策放 `docs/adr/`。
- 演示数据库文件（`*.sqlite`）、`admin-password.txt` 已在 `.gitignore`，不进仓库。

### 命名

- Python 用 snake_case，接口路径用小写加斜杠，如 `/api/key/rotate`。
- 前端变量用 camelCase，CSS 类名用小写连字符，如 `.stat-card`。
- 学生关联键统一叫 `owner_ref`，请求幂等键统一叫 `request_id`（前端传 `requestId`）。

### 安全约定（必须守）

- 密码存 scrypt 加盐哈希，不存明文，不写日志。参数见 `server.py` 的 `SCRYPT`。
- 密钥只存 SHA-256 摘要，明文只在发放那一次返回。
- 管理员账号密码只从环境变量读，任一项未设就关闭管理功能，不落库、不进仓库。
- 鉴权只认服务端会话令牌，不信前端传来的 `owner_ref` 或额度。
- 登录失败连续 5 次锁定 60 秒，防撞库。
- 所有 SQL 用参数化查询，不拼字符串。
- 写流水、扣额度、发赠送在同一事务内完成，用 `BEGIN IMMEDIATE` 先锁账户。
- 前端插入用户或接口数据时，优先用 `textContent` 和 `createElement`，不用 `innerHTML` 拼接外部字符串。当前流水渲染用了模板字符串，数据来自自己的后端；接入外部数据前要改成创建节点的写法。

### 数据与幂等

- 账户、流水、密钥的唯一事实来源是服务端数据库，前端展示不作授权依据。
- 赠送、消耗、密钥发放都靠唯一约束加 `request_id` 保证幂等，重复请求返回原结果。
- 流水是审计依据，消费和流水必须同一事务，不允许只改余额不写流水。

### 生产替换点

- `roster.py` 的演示名册换成学校真实名册，保持 `student_id_of`、`name_for`、`is_enrolled` 签名不变。
- `relay.py` 的模拟中转站换成真实中转站，保持发放、吊销、台账接口不变。
- 账号密码登录换成 HUST SSO 或 CAS，平台不保存校园密码。

### 改动流程

- 改架构、UI 规范、开发规范、对外接口前，先加或更新对应 ADR。
- 面向人读的文档（README、ADR、设计说明）按团队 `zh-tech-writing` 规范写：结论先行、短句、中英文间加空格。
- 提交信息用 `类型: 说明`，类型取 `feat`、`fix`、`docs` 等，与现有历史一致。
- 不提交演示数据库、密码、密钥到仓库。

## 后果

- 新共创者照这套约定走，代码风格和安全口径一致。
- 不引依赖、不走构建，上手和部署成本低，代价是复杂功能要自己用标准库实现。
- 安全约定是底线，违反要在评审时挡回。
