# 0009 个人访问令牌与 CLI/skill 边界

状态：草案
日期：2026-11-24

## 背景

用户要把平台的个人操作交给 agent 完成：提交作品、轮换密钥、消费额度，以及组织管理员的审核、精选、下架等。需要一个机器可用、带用户本人权限、可随时收回的凭据，加一套命令面和说明。现有登录只有浏览器 session（不透明 token，8 小时），不适合长期给 agent 用。

## 决策

### 个人访问令牌（PAT）

- 新增表 `pat_tokens`，字段含 id、user_id、token_hash（唯一）、token_hint、label、role_snapshot、org_snapshot、created_at、created_by、expires_at、last_used_at、revoked_at、revoked_by。
- 明文格式 `cpat_` 前缀加随机串，只存 SHA-256 摘要，明文只在铸造时返回一次。
- 有效期必填，范围 1 到 90 天，默认 30 天，不提供永久选项。
- 每个用户的 PAT 数量有上限，铸造带幂等。

### 权限判定（第一性原理）

- PAT 只证明「我是谁」，不决定「我能干什么」。
- 授权一律实时读当前身份：每次请求用当前的角色和准入状态判权，不用签发时的快照。被降级或停用的用户，手里的旧 PAT 立即失去对应权限。
- `role_snapshot` 只用于展示和审计，以及失效检测：当前权限比签发时缩小，就把该 PAT 判失效并提示重新签发，不静默降权继续用。
- disabled 立即失效，pending_review 沿用现有允许的只读范围。

### 能力面

- PAT 为全权一档：等于该用户当前角色在 authz.py 权限矩阵里真实拥有的全部权限，不额外加权，也不缩减。
- 据现有矩阵：组织成员可提交/撤回作品、轮换自己的钥、消费、做引导；组织管理员在此之上可审核、精选、下架本组织作品、看本组织账户；平台管理员才有吊销他人密钥、名单导入、全局下架。PAT 让 agent 能做的，就是持有人本人角色能做的那些，一件不多。
- 因此 PAT 不构成提权通道：组织管理员的 PAT 不能吊销密钥或导入名单，因为他本人就没有这两项权限。
- CLI 和 skill 对写操作，尤其对他人生效的下架等，建议 agent 二次确认。这是客户端操作约定，可被直接 HTTP 调用绕过，不是服务端强制的安全保证；真正的权限边界由服务端 authz 实时判定。所有写操作全部写入审计。

### 鉴权接入

- `principal_from_token` 按 `cpat_` 前缀分支到 PAT 校验：查摘要、校验未撤销且未过期、取当前 user_id、实时取当前角色与准入。其余 session 逻辑不变。
- PAT 与 session 并存，互不影响。`/api/logout` 只结束当前 session，不动 PAT。撤销 PAT 走专用接口，立即生效。
- 审计记录认证方式（session 或 PAT）、PAT 时记 pat_id、动作、对象和结果，用于区分同一用户交给不同 agent 的凭据。
- 铸造幂等与一次性返回：明文只在铸造响应里出现一次。铸造请求重放或响应丢失时，不再次返回原明文；按幂等键返回已存在记录的元数据（不含明文），由用户重新铸造一把新的。

### 接口与控件

- 新增 `POST /api/me/tokens`（铸）、`GET /api/me/tokens`（列，只回掩码和状态）、`DELETE /api/me/tokens/{id}`（撤）。
- 个人中心加「获取我的 agent 工具包」控件，点按铸出一个 PAT，打包返回 PAT 明文（一次性）、base URL、CLI 和 SKILL。

### CLI 与 skill

- `campus-cli` 只用 Python 标准库，支持 `--json`。凭据只从 `CAMPUS_PAT` 环境变量读，不进命令行参数、URL、日志。
- CLI 覆盖用户自助接口和组织管理员接口，与后端 HTTP 路由一一对应。对 401、403、404、409、413、429、5xx 给稳定退出码和可读错误，不打印 Authorization 头、token 或堆栈。
- SKILL.md 只写用法和环境变量名，不含任何 token、密码或敏感信息。

## 后果

- agent 能以用户本人身份完成平台内的全部个人工作，凭据可限时、可吊销、可审计。
- 降权或停用后，旧 PAT 不能继续用作提权通道。
- 把 PAT 交给 agent 等于把账户完整能力交出去，所以 PAT 必须限时和可撤，这是本决策的硬约束。
- session 和 PAT 两套凭据并存，各自独立吊销。
- 本条取代 0004「鉴权只认服务端会话令牌」的约定，扩展为服务端同时认 session 与 PAT；两者都只存摘要、都不作前端授权依据。
- pending_review 沿用 0005 现有允许范围（含 onboarding 写操作，并非纯只读）；该范围缩小即触发 PAT 失效提示。
