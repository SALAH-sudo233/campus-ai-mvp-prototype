# 校园 AI 创作平台 MVP 原型

这个原型演示学生登录、领取 Token 额度，以及从中转站拿到调用 AI 工具用的密钥。所有数据都是演示数据，中转站的上游通道也是假的。

## 运行

原型现在有后端，需要先启动它。后端只用 Python 标准库，不用安装依赖。

```bash
DEMO_ALLOW_RESET=1 python3 server.py
```

浏览器打开 `http://127.0.0.1:8080`。`DEMO_ALLOW_RESET=1` 只用于演示，开启后页面底部的“重置演示数据”才会生效。

可用环境变量：

| 变量 | 默认值 | 作用 |
|---|---|---|
| PORT | 8080 | 监听端口 |
| HOST | 127.0.0.1 | 监听地址 |
| DEMO_DB | demo-backend.sqlite | 账户、流水、会话数据库 |
| DEMO_RELAY_DB | demo-relay.sqlite | 中转站数据库 |
| DEMO_ALLOW_RESET | 未设置 | 设为 1 才开放 /api/reset |
| MOCK_RELAY_DOWN | 未设置 | 设为 1 模拟中转站不可用 |
| ADMIN_PASSWORD | 未设置 | 设置后开启中转站管理后台 `/admin`，未设置则关闭管理功能 |

GitHub Pages 上的公开页面是纯静态的，跑不了后端。登录、注册、领取密钥只能在本地启动 `server.py` 后体验。

## 一键启动

原型跑在 yb-dev 上，只监听 `127.0.0.1`。在服务器上启动：

```bash
cd hust-campus-ai-prototype
ADMIN_PASSWORD=换成你的口令 DEMO_ALLOW_RESET=1 python3 server.py
```

- 学生端：`http://127.0.0.1:8080`
- 中转站管理后台：`http://127.0.0.1:8080/admin`，用 `ADMIN_PASSWORD` 的口令登录。不设 `ADMIN_PASSWORD` 时管理后台关闭。

在本机（Mac）访问服务器上的原型，用 SSH 端口转发把远端 8080 映射到本地：

```bash
ssh -N -L 8080:127.0.0.1:8080 你的用户名@yb-dev
```

转发开着时，本机浏览器打开 `http://127.0.0.1:8080` 和 `http://127.0.0.1:8080/admin` 即可。

## 外部访问

外部访问使用反向代理。代理负责公网 HTTPS，`server.py` 继续只监听 `127.0.0.1`。实际地址在部署拍板后填入，本文先用 `https://<待定域名>` 表示。

### 部署前提

外部人员访问前，需要先完成以下事项：

1. 为服务器准备公网域名，并让 `https://<待定域名>` 指向反向代理。
2. 在服务器上启动反向代理。以下是 Caddy 的最小转发示例，完整部署参数按安全方案执行：

   ```caddy
   <待定域名> {
       reverse_proxy 127.0.0.1:8080
   }
   ```

3. 在同一台服务器上启动原型后端。后端保持本地监听，不要把 `HOST` 改成 `0.0.0.0`：

   ```bash
   cd hust-campus-ai-prototype
   HOST=127.0.0.1 PORT=8080 python3 server.py
   ```

   `ADMIN_PASSWORD` 需要由部署方在服务器环境中安全设置。未设置时，`/admin` 会关闭。演示重置功能只有在需要时才设置 `DEMO_ALLOW_RESET=1`，是否对外开放按安全方案执行。

公网用户不需要知道服务器地址、8080 端口或 SSH 登录信息。代理配置生效后，所有人都从以下地址进入：

```text
学生端：https://<待定域名>/
管理员端：https://<待定域名>/admin
```

### 学生端操作

1. 打开 `https://<待定域名>/`。
2. 选择“校园邮箱”或“学号”，输入身份和至少 8 位密码。
3. 首次使用点击“注册”。原型会发放 100,000 Token，并申请一枚模拟中转站密钥。
4. 立即复制页面显示的密钥明文。密钥明文只在发放时显示一次，之后页面只显示掩码。
5. 后续访问使用相同身份和密码点击“登录”。登录后可以查看余额、流水，模拟消耗 Token，或重新生成密钥。

这里的登录、Token 和密钥都属于演示流程。原型不连接真实校园认证，也不连接真实 AI 中转站。

### 管理员端操作

1. 打开 `https://<待定域名>/admin`。
2. 输入部署时设置的 `ADMIN_PASSWORD`。
3. 按学号、邮箱或姓名搜索实名台账。
4. 查看学生编号、登录身份、姓名、密钥掩码和密钥状态。
5. 需要使当前密钥失效时，点击对应记录的“吊销密钥”。

管理员页面只在服务端设置了 `ADMIN_PASSWORD` 时可用。管理员口令不写入仓库，也不放进本文档。

### 访问边界

- 这是演示原型，数据库、实名名册和中转站上游数据都是演示数据。
- GitHub Pages 只能提供静态页面，不能替代运行 `server.py` 的后端。
- 公网域名、HTTPS、访问控制和其他安全配置按安全方案执行；本节只说明原型的访问路径。

## 中转站管理后台

管理后台面向中转站管理员，不是学生页面：

- 实名台账列表：学生编号、身份类型、登录身份、姓名、密钥掩码、密钥状态。
- 按学号、邮箱或姓名搜索。
- 吊销某学生的当前密钥，吊销后立即失效，学生下次登录会重新发放。

姓名来自内置演示名册（学号 `2024001001` 起连号的 200 人，固定随机种子）。名册外的学号照常注册，姓名留空，只做展示，不做准入。生产版把演示名册换成学校真实名册，真实名册不进仓库。

## 已包含

- 校园邮箱或学号加密码注册、登录。密码至少 8 位，服务端存加盐哈希。
- 连续 5 次登录失败后锁定 60 秒。
- 注册时一次性赠送 100,000 Token，按账户只发一次。
- 注册和登录成功后，由模拟中转站发放一枚密钥。密钥明文只显示一次，之后只显示掩码。
- 中转站维护实名台账，管理后台 `/admin` 可按学号、邮箱、姓名搜索学生并吊销密钥。
- 工作台可重新生成密钥，旧密钥立即失效。
- 余额、累计消耗、Token 流水和模拟消耗。

## 接口

| 接口 | 作用 |
|---|---|
| POST /api/register | 邮箱或学号加密码注册，返回令牌和密钥明文 |
| POST /api/login | 校验密码，返回令牌和密钥掩码 |
| GET /api/me | 按令牌返回账户视图 |
| POST /api/key/rotate | 作废旧密钥，发新密钥 |
| POST /api/consume | 扣减 Token，带请求编号幂等 |
| POST /api/logout | 令牌失效 |
| POST /api/admin/login | 校验管理员口令，返回管理员令牌 |
| GET /api/admin/accounts | 管理员令牌鉴权，返回实名台账，支持 `?q=` 搜索 |
| POST /api/admin/revoke | 管理员令牌鉴权，按 owner_ref 吊销当前密钥 |

## 生产接入边界

- 原型用账号密码模拟身份认证。密码只是原型临时手段，正式版接华中科技大学官方 SSO 或 CAS，不在平台保存校园密码。
- 中转站按设计维护实名台账：收到学生编号（owner_ref）后关联登录身份与姓名，管理员可据此查看和吊销。原型的中转站是模拟实现，以后接入真实中转站。
- 学生编号当前是登录身份的 SHA-256 截断，只当台账和密钥的关联键用，不是强匿名化。
- 邮箱账号和学号账号在原型里是两个独立账户，不做归并，是已知限制，生产版由学校统一认证解决。
- 姓名来自内置演示名册，名册外学号姓名留空、照常注册、只做展示不做准入。真实名册以后接入，不进仓库。
- 中转站的真实供应商、计费口径和密钥格式还没有定。
