# 校园 AI 创作平台原型

这个原型演示学校组织内的额度、密钥、教师看板、名单导入、新手引导和作品广场。数据都是演示数据。技术栈保持 Python 标准库、SQLite 和原生 JavaScript，不新增运行时依赖。

## 角色与入口

平台分三层：平台 → 组织 → 组织成员。组织内只有两种角色：

| 角色 | 试点文案 | 能做什么 |
|---|---|---|
| `platform_admin` | 平台管理员 | 创建组织、查看全部组织树与审计、批量分配额度、全局下架作品 |
| `org_admin` | 教师 | 查看本组织总览、趋势、排行、成员明细和密钥掩码，导入名单、审核作品、精选与下架 |
| `org_member` | 学生 | 查看自己的额度、密钥、流水，提交和撤回作品，完成新手引导 |

管理员入口在产品右上角。学生登录页只保留校园邮箱和学号两种登录方式，不再放角色切换标签。

主要页面：

| 路径 | 页面 |
|---|---|
| `/` | 学生登录与工作台 |
| `/teacher` | 教师端（组织管理员） |
| `/admin` | 平台管理（环境变量账号） |
| `/import` | 名单导入 |

部署在 `/app/` 前缀下时，页面继续通过脚本自身路径推导接口基址，不需要改前端代码。

## 已经实现

### 组织与权限

- `organizations`、`users`、`user_identities`、`org_memberships`、`org_policies` 等新表。
- `schema_migrations` 版本表，每个版本一个事务。重复执行只补未完成的版本。
- 旧 `students`、`ledger`、`sessions` 和中转站台账按 `owner_ref` 回填 `user_id` 与 `org_id`，旧字段保留。
- 试点组织“华中科技大学软件学院”和 200 人名册自动建立。名册外历史账户进入 `pending_review`，余额和流水保留。
- 服务端权限矩阵，三种角色按资源和动作判断。跨组织请求返回 403，不泄露资源是否存在。

### 名单导入

- 只收 UTF-8 CSV，固定列 `external_ref,student_id,email,name,role,status`。
- 上限为 10 MB、10,000 行、单字段 256 字符、整行 4 KB。
- 先预览再确认，预览不写成员表。确认幂等，同一批次重复确认返回原结果。
- 校验列数、身份格式、角色与状态、文件内重复、现有成员冲突、公式前缀、控制字符和引号。
- 错误报告对邮箱和学号脱敏，公式前缀在导出时转义。
- 导入上传有独立的 10 MB 限制；其他 JSON 接口仍是 64 KB。

导入页 `/import` 提供模板下载、列定义和常见错误。组织管理员只能导入本组织，平台管理员可以选择组织。

### 教师端

- 组织总览：成员数、活跃成员、总消耗、剩余额度。
- 按天趋势，最多 90 天，服务端截断并返回 `truncated`。
- 手写 SVG 面积线、活跃度分布、90 天热力格和额度消耗排行。
- 成员列表含姓名、学号、角色、用量、密钥掩码；支持搜索、吊销密钥和调整准入状态。
- 学生作品审核、精选、取消精选和下架；精选关系按组织单独保存。
- 数据接口失败时显示“数据暂不可用”和时间范围，不把 0 当作成功。

### 新手引导与作品广场

- 四步开始卡片：认识团队、选择工具、做出作品、探索平台。
- 四步都可以跳过，跳过、完成和中途退出分别记录。
- 新注册用户自动进入；老用户在工作台看到“开始指南”提示，不强制弹出。
- 进度存服务端，跨设备恢复；提交带 `expectedRevision`，并发修改返回 409。
- 第 3 步是可交互的演示小工具，全程标注“演示”，不调用真实 AI，不扣真实额度。
- 视频位由配置控制，素材地址为空时整块不显示。
- 产品广场展示种子演示作品和本组织已审核作品；作者可以随时撤回；教师可以审核和精选。

## 本地运行

```bash
python3 server.py
```

浏览器打开 `http://127.0.0.1:8080`。首次启动会在当前目录创建两个演示数据库。`*.sqlite` 已在 `.gitignore` 中。

常用环境变量：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `PORT` | `8080` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `DEMO_DB` | `demo-backend.sqlite` | 账户、组织、作品和引导数据库 |
| `DEMO_RELAY_DB` | `demo-relay.sqlite` | 模拟中转站数据库 |
| `DEMO_ALLOW_RESET` | 未设置 | 设为 `1` 才开放重置入口 |
| `MOCK_RELAY_DOWN` | 未设置 | 设为 `1` 模拟中转站不可用 |
| `ADMIN_USERNAME` | 未设置 | 平台管理员账号 |
| `ADMIN_PASSWORD` | 未设置 | 平台管理员密码 |

管理员账号和密码只从环境变量读取，不落库，不进仓库。任一项未设置时，平台管理登录返回 404。

### 迁移

服务启动时自动执行迁移。也可以显式运行：

```bash
python3 migrate.py
```

迁移可重复执行。失败时回滚当前版本，不留下半写状态。

## 测试

测试只用标准库 `unittest`：

```bash
python3 -m unittest discover -s tests -v
```

覆盖范围包括迁移幂等与旧数据回填、三种角色权限与跨组织 403、导入预览与确认、引导并发、作品状态机、旧接口字段快照，以及真实进程的端到端流程。端到端用例会启动独立服务，使用临时数据库和随机端口。

## 部署片段

`deploy/nginx-campus-locations.conf` 为导入预览路径单独配置 `client_max_body_size 10m`，其他 `/app/` 接口仍为 64 KB。修改线上 nginx 不在本仓库的自动部署范围内。

## 已知边界

- SQLite 单机适合试点，不支持多实例并发写。
- 邮箱账号和学号账号仍按旧模型存为两个 `owner_ref`，但可以关联同一用户和组织成员关系。
- 作品只是原型数据，不执行学生提交的脚本，也不接真实创作执行。
- 真实学校统一认证、真实中转站、XLSX 导入、支付充值和工具维度埋点不在本版范围。
